# ReLU Surrogate Baseline

## Purpose

This is a first reproducible surrogate experiment using the compressor
responses already generated by TurboCompGPU. It recreates the core
hackathon method—fit a ReLU network to sampled compressor operation—without
claiming to reproduce the unavailable legacy-station data or its results.

## Data and scope

The default input is
benchmarks/results-compressor-map/map.csv. The file contains 140 solve rows:
the same operating conditions are evaluated with independent and continuation
initialization. The training script deduplicates these paired rows by
thermodynamic model, mass flow, and speed after checking that their targets
agree. That leaves 35 unique operating points per thermodynamic model.

The initial surrogate uses:

- Inputs: mass flow and rotational speed.
- Outputs: total outlet temperature, total outlet pressure, and specific work.
- Separate network per thermodynamic model.
- Fixed inlet state, impeller geometry, slip, prewhirl, and entropy-generation
  setting from the source benchmark.

The current result is a two-input map under one fixed setup. It does not yet
interpolate over inlet pressure or temperature, geometry, gas composition,
loss parameters, or transient state.

## Run

Install NumPy and PyTorch in the Python environment, then run from the
repository root:

    python3 benchmarks/train_relu_surrogate.py       benchmarks/results-compressor-map/map.csv       --output-dir build/relu-surrogate

The script trains a small fully connected ReLU network. Positive outputs are
modeled in natural-log coordinates. It reports maximum, 99th-percentile, and
RMS relative errors for each target.

The default CSV contains a 7-by-5 grid. To regenerate the same fixed-condition
map at a denser resolution, build the C++ map exporter and pass the number of
flow and speed samples:

    cmake --build build-cpu -j2 --target turbocompgpu_compressor_map_envelope
    ./build-cpu/turbocompgpu_compressor_map_envelope \
      build/relu-surrogate/map-21x21.csv 21 21
    python3 benchmarks/train_relu_surrogate.py \
      build/relu-surrogate/map-21x21.csv \
      --output-dir build/relu-surrogate/fit-21x21

The denser file contains 21-by-21 conditions for each of two thermodynamic
models. Each condition has independent and continuation rows; the trainer
checks and deduplicates those pairs, leaving 441 unique samples per model.
Flow, speed, inlet conditions, geometry, and loss settings retain the existing
benchmark ranges and fixed values.

Validation leaves out one complete rotational-speed line at a time. The
lowest and highest speed folds are extrapolation checks; the interior folds
test interpolation across speed. Independent and continuation rows are not
allowed to leak across the split because duplicate conditions are deduplicated
before training.

Artifacts:

- build/relu-surrogate/report.json
- build/relu-surrogate/speedline_holdout.csv
- build/relu-surrogate/ideal_gas.pt
- build/relu-surrogate/pengrobinson.pt

## Interpretation

This is a baseline and a feasibility measurement, not a qualified compressor
surrogate. Its labels come from the current physics model, whose incidence
and loss closures remain partly exploratory and whose maps are numerically
tested rather than experimentally validated. Good holdout error means the
network approximates this model over the stated fixed-setup domain; it does
not establish agreement with a commercial station or physical compressor.

If the errors are unacceptable, the next step is to generate a denser
structured grid directly from the validated C++ evaluator, then repeat
structured holdouts on flow and speed regions. Only after the map surrogate
is qualified should it be exposed through the pipe/compressor interface.
